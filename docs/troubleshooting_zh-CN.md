# 故障排查

排查问题时，先确认当前使用的项目版本、启动方式、端口和配置文件。Visual Studio、命令行和 Docker 可能使用不同的地址或工作目录。

## 1. 服务无法启动

检查：

- 是否安装 .NET 8；
- `dotnet restore TangYuan.sln` 是否成功；
- 端口是否已被占用；
- SQLite 路径是否有效；
- `appsettings.json` 是否为有效 JSON；
- `skill-manifest.json` 是否存在且格式正确；
- 项目移动到 `src/` 后，解决方案是否引用正确路径。

推荐命令：

```bash
dotnet build TangYuan.sln -c Release
dotnet run --project src/OpenTangYuan --urls "http://localhost:54124"
```

## 2. Swagger 无法访问

检查：

- 实际启动端口；
- 当前环境是否启用了 Swagger；
- 是否使用了 HTTP 或 HTTPS；
- 反向代理路径是否正确；
- 生产配置是否关闭或限制了 Swagger。

## 3. 无法发送邮件

检查：

- SMTP 服务器和端口；
- SSL/TLS 设置；
- 发件邮箱和授权码；
- 邮箱服务商是否允许 SMTP；
- 是否要求专用授权码；
- 网络或防火墙是否阻止连接；
- 收件人和附件路径是否合法。

## 4. 无法搜索或读取邮件

检查：

- IMAP 服务器和端口；
- IMAP 是否在邮箱后台启用；
- 授权码是否正确；
- 邮箱服务商是否限制第三方客户端；
- `contextKey` 是否与前一次搜索一致；
- 读取的 `index` 是否存在于当前搜索结果中。

## 5. 无法下载附件

检查：

- 是否已经先搜索邮件；
- 指定的邮件索引是否正确；
- `savePath` 是否存在或可创建；
- 保存目录是否位于允许访问的范围；
- 运行账户是否具有写权限；
- 磁盘空间是否足够。

## 6. 无法打开或打印文件

检查：

- 文件是否存在；
- 路径是否位于 `AllowedRoots`；
- 运行账户是否具有权限；
- 系统是否安装该文件类型的默认应用；
- 打印机和打印服务是否可用；
- 路径中的转义和引号是否正确。

## 7. 文件搜索没有结果

检查：

- 关键字和扩展名是否正确；
- Windows Search 或 Everything 服务是否可用；
- 搜索目录是否已经建立索引；
- 运行账户是否能访问目标目录；
- 文件是否位于白名单范围内。

## 8. 浏览器任务失败

检查：

- Playwright 是否完整安装；
- 浏览器运行资源是否存在；
- 目标网站是否需要登录；
- CSS 选择器是否仍然有效；
- 页面是否被 CAPTCHA、多因素认证或反自动化机制阻止；
- Session 是否已经关闭；
- 下载目录是否可写。

## 9. 截图失败

检查：

- 是否在具有桌面会话的 Windows 环境运行；
- 服务是否作为无法访问桌面的后台账户运行；
- 本地应用是否已经打开；
- 网页截图是否误用了桌面截图技能；
- 输出目录是否存在且可写。

## 10. 后续步骤无法引用前一步结果

检查：

- 步骤编号是否正确，例如 `step0`、`step1`；
- 前一步是否成功；
- 字段路径是否与真实响应一致；
- 是否使用了正确大小写；
- 模板是否写成 `{{step0.data.path}}` 的形式；
- 是否错误地猜测了返回字段。

建议在调试模式下查看每一步的解析参数和结果摘要。

## 11. 技能不存在

可能原因：

- `SkillCode` 拼写错误；
- 当前部署未提供该扩展技能；
- `skill-manifest.json` 未加载；
- 数据库中没有指定工作流；
- Agent 使用了旧版本的技能名称。

正确做法是重新调用 `GetSkillListForAI`，不要依赖缓存的技能目录。

## 12. 副作用操作被阻止

可能原因：

- 请求重复；
- 路径不在白名单中；
- 程序不在白名单中；
- 参数缺失；
- 安全策略拒绝；
- 当前身份没有权限；
- 操作需要人工确认。

不要尝试绕过策略。应根据错误信息调整配置或让管理员授权。

## 13. Docker 中桌面功能不可用

这是预期限制。Docker 更适合验证 API 和服务端逻辑，通常不能直接访问 Windows 交互桌面。

需要截图、打开文档或调用桌面程序时，应在 Windows 本地运行时中执行。

## 14. Git 或 Visual Studio 在移动目录后异常

检查：

- `.sln` 是否仍在仓库根目录；
- `.csproj` 是否已经添加到新的 `src/OpenTangYuan/` 路径；
- 是否需要关闭 Visual Studio 并删除本地 `.vs/` 缓存；
- `git status` 是否能在命令行正常运行；
- `.gitignore` 是否忽略 `.vs/`、`bin/` 和 `obj/`；
- Dockerfile、README 和构建脚本中的旧路径是否已经更新。

## 15. 收集诊断信息

报告问题时建议提供：

- OpenTangYuan 版本或提交号；
- 操作系统和 .NET 版本；
- 启动方式；
- 调用的 API 和 `SkillCode`；
- 经脱敏的请求参数；
- HTTP 状态码和 `errorCode`；
- 经脱敏的日志；
- 是否能通过 Swagger 重现。

不要在 Issue 中公开邮箱授权码、API Key、真实内部路径、私人邮件正文或敏感截图。
