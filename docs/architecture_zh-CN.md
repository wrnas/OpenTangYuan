# 架构与运行机制

## 1. 设计目标

OpenTangYuan 面向这样一类任务：外部 AI Agent 能够理解需求和规划步骤，但真实执行必须访问本地文件、邮箱、浏览器、桌面应用、企业消息平台或内部系统。

系统将任务理解与执行权限分离：

```text
外部 Agent
  ├─ 理解用户意图
  ├─ 查询可用能力
  ├─ 选择工作流或内置技能
  └─ 生成结构化参数
        │
        ▼
OpenTangYuan 可信本地运行时
  ├─ 验证请求与参数
  ├─ 执行工作流
  ├─ 调用本地技能
  ├─ 管理上下文
  └─ 返回结构化结果
        │
        ▼
本地与企业资源
```

外部 Agent 不直接持有本地执行权限。文件、邮件内容、截图和内部系统数据由本地运行时处理。

## 2. 主要组件

| 组件 | 职责 |
|---|---|
| 能力目录 | 汇总数据库工作流和 `skill-manifest.json` 中的内置技能。 |
| 技能清单 | 描述技能名称、用途、动作、参数、示例、约束和副作用。 |
| 工作流仓库 | 保存可复用的多步骤任务定义。 |
| 工作流运行时 | 负责步骤调度、模板解析、上下文传递、执行和失败报告。 |
| 内置技能执行器 | 调用邮箱、文件、浏览器、桌面、本地程序和企业消息能力。 |
| 统一 API | 向 Agent、桌面客户端和其他系统提供发现、查询和执行接口。 |
| 安全控制 | 结合认证、路径白名单、程序白名单、策略校验和日志限制执行范围。 |

## 3. 能力发现

推荐的能力发现流程为：

```text
1. GetSkillListForAI
   获取工作流和内置技能的摘要

2. GetSkillAction 或 GetBuiltinSkillDetail
   获取选定能力的详细步骤或参数

3. ExecuteSkill 或 ExecuteSkillForCoze
   提交任务并执行
```

这种方式避免 Agent 在每次对话中加载完整技能字典，也允许在不修改 Agent 主逻辑的情况下增加新技能。

### 工作流优先

当能力目录中已经存在能够完成任务的工作流时，Agent 应优先复用该工作流。这样可以减少重复规划，并使常用任务的执行步骤更稳定。

### 内置技能作为组合基础

当没有匹配的工作流时，Agent 可以查询一个或多个内置技能的详细定义，然后创建临时工作流。

## 4. 执行模式

统一执行入口支持三种模式：

| 模式 | 识别方式 | 用途 |
|---|---|---|
| 内置技能 | 无 `Steps`，且未匹配数据库工作流 | 执行一个原子能力。 |
| 数据库工作流 | 数据库中存在相同 `SkillCode` | 执行预先保存的多步骤任务。 |
| 临时工作流 | 请求中包含非空 `Steps` | 执行 Agent 或客户端动态生成的任务。 |

## 5. 工作流运行时

工作流运行时按顺序执行步骤：

```text
接收工作流步骤
      ↓
初始化执行上下文
      ↓
解析当前步骤参数中的模板变量
      ↓
调用对应内置技能
      ↓
将结果保存为 stepN
      ↓
后续步骤引用前序结果
      ↓
返回最终结果与执行状态
```

运行时主要承担：

- 步骤调度；
- 参数模板解析；
- 上下文管理；
- 内置技能调用；
- 结果封装；
- 调试日志；
- 错误和失败报告。

## 6. 上下文传递

每一步的结果会按顺序写入上下文：

```text
step0
step1
step2
...
```

后续步骤可以通过模板变量引用：

```text
{{step0}}
{{step0.path}}
{{step0.data.path}}
{{step0.data.firstPath}}
{{step1.result}}
```

运行时应使用前一步实际返回的数据结构解析模板。Agent 不应猜测中间文件路径或硬编码运行时产生的值。

## 7. 云端与本地边界

| 区域 | 可以处理的内容 | 不应承担的内容 |
|---|---|---|
| 外部 Agent | 用户意图、能力摘要、参数定义、任务规划 | 直接读取本地文件、邮箱或内部系统数据 |
| 本地运行时 | 执行、敏感数据处理、权限验证、上下文管理 | 替代 Agent 完成自然语言理解 |
| 企业系统 | 业务数据和操作能力 | 直接暴露给不受控的外部 Agent |

实际部署中，外部 Agent 与本地运行时之间的通信仍需使用 HTTPS、网关、VPN、IP 限制或其他访问控制。

## 8. 副作用控制

以下操作会改变外部状态：

- 发送或回复邮件；
- 下载、复制、移动、重命名或删除文件；
- 打印文件；
- 启动程序；
- 向企业消息平台发送内容；
- 调用内部系统写操作。

对这类操作，应采用以下策略：

1. 执行前验证必要参数；
2. 限制允许访问的路径和程序；
3. 成功后立即停止，不重复执行；
4. 记录关键执行日志；
5. 对高风险任务增加人工确认；
6. 失败时限制重试次数。

## 9. 扩展方式

### 新增内置技能

实现新的执行逻辑，并在 `skill-manifest.json` 中登记能力、参数、动作、示例和约束。

### 新增工作流

将多个内置技能组合为步骤序列，保存到数据库或通过管理接口创建。

### 集成新企业系统

可通过以下方式接入：

- REST API；
- 浏览器自动化；
- 本地命令行工具；
- 自定义插件；
- 企业消息 Webhook；
- 内部服务网关。

### 扩展安全策略

可以增加角色权限、审批流程、路径策略、程序策略、操作审计和告警规则。
